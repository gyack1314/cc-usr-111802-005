# 山地流域数据约定

observation、reference、rule 三种记录分别表示观测、参照和区域规则，用于单期指标比较。metric、region、unit 共同表示现有单期可比口径，来源版次与取得时间独立保留。

## 跨季方案

跨季分析另有四类记录，各按自己的时间尺度参与计算，互不换算：

| kind | 含义 | 时间尺度 | 记录方式 |
| --- | --- | --- | --- |
| `meltwater` | 冰川融水估计 | 月 | 每月一条 |
| `inflow` | 来水观测 | 月 | 每月一条 |
| `storage` | 库容 | 区间 | 用 `valid_from`/`valid_to` 覆盖月份 |
| `demand` | 灌溉需求 | 月 | 每月一条 |

每条记录带 `unit` 与 `value`。`valid_from` 可写完整日期或 `YYYY-MM`。一个方案内各类输入必须同单位才能相加；单位不同时不得相减。

方案（scenario）把各类来源版本与单位绑定成一个具体口径：

```json
{"id":"irrigation-2026","start":"2026-07","end":"2026-09","unit":"m3",
 "meltwater":{}, "inflow":{}, "storage":{"cap-summer":"r1"}, "demand":{}}
```

未绑定的记录取 `known_at` 之前的最新版本；绑定某条记录后固定为该版本，其余记录仍取当时最新版本。绑定在 `known_at` 时尚未收到的版本会报错。

## 可供水与承诺

每月可供水 = 融水估计 + 来水观测；可供水不超过库容；缺口 = 灌溉需求 − min(可供水, 库容)。缺库容或缺来水的月份不形成承诺，标为“缺库容或来水资料”。

## 差异性质

比较两次方案或两个方案时，逐月给出：

* **估计口径改变**：来源版本变了，但该月可供水量与缺口不变；
* **承诺变化**：可供水量或缺口改变，必须列入受影响月份；
* **可供水区间缩短 / 恢复**：库容区间修订使某月能否承诺发生变化；
* **同口径无差异 / 不可直接比较**：单位或月份范围不一致时不做数值比较。

只修订融水估计也可能改变缺口；此时按“承诺变化”处理并指出月份，而不是当作口径变化。

## 报告归档

生成的报告写入 `reports` 表。相同输入必须得到相同正文与指纹；同一报告标识下正文不同的写入会被拒绝，不得用新估计覆盖旧决定。`replay` 只读取归档正文，不重新读来源，因此历史调度报告可按当时已知资料复现。
